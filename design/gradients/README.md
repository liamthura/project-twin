# Gradient assets

Generated from GRADIENTOOL (gradientool.com), a canvas 2D generator using
layered linear and radial gradients with grain.

Every asset here is follows the reference ramp (ink, blue, pink, cream).
indigo, clay, verdigris. Nothing else. See the spec at
docs/superpowers/specs/2026-08-04-mygist-landing-design.md.

Regenerating: open the tool, set the parameters recorded beside each asset
below, export at 2x, and replace the file in place. Keep the parameter block
up to date or the next person cannot reproduce it.

## Assets

Generated by driving the tool with Playwright rather than by hand (see
`.superpowers/sdd/2026-08-04-mygist-landing-figma/task-5-report.md` for the
full method). Colour stops and every other field below were set on the live
app state (`window.GR_DEBUG.state`, the same object the sliders/inputs write
to — exposed unconditionally by the tool's own script) and confirmed by
reading that state back after rendering, then the pixels were read straight
off the `<canvas id="view">` via `toDataURL`, never the export button.

### edge-strip-light.png
2880×24 · stops: indigo #3D5DDB @ 0%, clay #E47B4E @ 50%, verdigris #39757F @ 100%
layer: direction `up` · gradMap `field` · layout `linear` · shape one-peak (peakPos 0.5) · depth 1.0 · count 9 · widthExp 0 · gap 0 · jitter 0 · mirror off · opacity 1
background: bgColor #FAFAF9 (paper)
relief: grain 0.52 · seam 0.05 · depth3d 0.55
treatment: contour / filled bands · frequency 6 · weight 0.18 · invert off · colour mode `original`

Generation note: the tool normalises any custom aspect ratio so its *shorter*
side renders at 1000px (×3 internal supersample), so the literal 2880:24
ratio (120:1) demands a ~360,000px-wide canvas — confirmed empirically to
come back blank (Chromium silently fails to back a canvas that large; content
outside that failure size renders fine). Worked around by generating on a
200×2880 *portrait* canvas with `direction: up` instead of `right` (bars are
columns spanning the full width with no gap, vs. `right`'s bars which taper
and leave a jagged unpainted wedge at one edge — full coverage only appears
once `depth` is pushed to 1.0, above the slider's own 0.9 ceiling but
accepted by the state object directly), then rotating that render −90° and
resampling to the exact 2880×24 output in an offscreen canvas before
`toDataURL`. A ~25px-wide paper-coloured fade survives at the very left edge
from that rotation seam — palette-compliant (it's `bgColor`, one of the five)
but worth knowing about if it needs cleaning up later.

### hero-field-light.png
2880×1600 · stops: indigo #3D5DDB @ 0%, indigo #3D5DDB @ 60% (hold), paper #FAFAF9 @ 100%
layer: direction `right` · gradMap `field` · layout `linear` · shape one-peak (peakPos 0.5) · depth 1.0 · count 9 · widthExp 0 · gap 0 · jitter 0 · mirror off · opacity 0.9
background: bgColor #FAFAF9 (paper)
relief: grain 0.15 · seam 0.02 · depth3d 0.15 — reduced from the tool's defaults (0.52 / 0.05 / 0.55) because the brief calls for this field soft and low-contrast; the defaults produced a visibly noisy, high-relief bar chart, wrong for something sitting behind a mockup
treatment: none

Generation note: rendered directly at aspect `custom` 2880:1600 — well inside
the tool's working canvas size, no workaround needed — then downsampled to
the exact 2880×1600 output via the same offscreen-canvas `toDataURL` method.
The single-peak bar shape tapers softly at both left and right edges even at
depth 1.0 for this aspect ratio, giving a centred indigo glow with paper
falloff on both sides rather than a one-sided falloff; kept as-is since it
reads as "soft field," matching the brief better than fighting for a harder
edge.
