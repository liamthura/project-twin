title: Manifest reference
description: Every key a section pack manifest accepts, with a real example of each.
---

The exhaustive companion to [Section packs](/run/section-packs), which is the
walkthrough. Every example here is copied from a pack that ships.

The authority is `backend/section_packs/meta_schema.json`. Point your editor at
it with `"$schema": "../meta_schema.json"` and it validates as you type. Every
object in a manifest is closed (`additionalProperties: false`), so a key this
page does not list is a startup error rather than a key silently ignored.

## Top level

| Key | Type | Required | Purpose |
|---|---|:--:|---|
| `key` | string | ● | Section key. Must equal the directory name. Lowercase `snake_case`. |
| `title` | string | ● | Display name in the Sections manager and the editor. |
| `description` | string | ● | One line, shown under the title in the Sections manager. |
| `core` | boolean | ● | `true` means the section can never be disabled. Only profile, preferences and the learning log are core. |
| `position` | integer | ● | Order in the editor's section list. |
| `defaults` | object | ● | The empty shape a new account starts with. |
| `id_lists` | array | ● | `[path, prefix]` pairs. Rows in each array get ids like `prefix_a1b2c3`. |
| `sections` | array | ● | One or more nodes. See [Nodes](#nodes). |
| `$schema` | string | | Points at the meta-schema for editor validation. |
| `default_enabled` | boolean | | Defaults to `true`. New packs set `false`. |
| `scope_contributions` | object | | `{scope: [key, ...]}`. Omit a scope to stay out of it. |
| `mcp_entities` | object | | Hand-written entities for a storage path no node can imply. See [mcp_entities](#mcp_entities). |

There is no `entities` key. The write vocabulary is derived from the field
descriptors in `sections`; see [The derived contract](#the-derived-contract).
There is no `ui` wrapper either, and no `capture_triggers`: nodes live at the
top-level `sections`, and the keyword matcher `capture_triggers` fed was retired
in favour of [proposals](/use/capture).

### `id_lists`

```json title="section_packs/media/manifest.json"
"id_lists": [["items", "media"]]
```

Every named path must be a list in `defaults` **and** be bound by a top-level
`list` node, and every prefix must be unique across every pack in the repository.

### `scope_contributions`

```json title="section_packs/aesthetics/manifest.json"
"scope_contributions": { "minimal": ["styles"], "personal": ["styles"] }
```

The keys are `minimal`, `professional`, `personal`, `learning` and `full`; any
other name is a `PackError` at boot. Each value names top-level keys of
`defaults`, and a name that is not a key of `defaults` is also a `PackError`,
because it would contribute nothing to context output.

No pack declares `full`. `get_context(scope: "full")` returns every enabled
section whatever the manifests say, so a `full` entry is accepted and then never
read. Your section also gets its own scope token for free: `get_context(scope:
"<key>")` works whether or not it contributes to any global scope.

<Callout>
One section reaches every scope without declaring anything here: preferences,
through `sections.ALWAYS_ON`, a hard-coded field bundle. Its
`scope_contributions` is `{}`. Do not copy that pattern. It is a deliberate
one-off for the fields that should never be scoped away.
</Callout>

## Nodes

A node's `kind` states the shape of the value at its `path`. The rest of the
format follows from that.

| `kind` | The value at `path` is | Carries |
|---|---|---|
| `group` | nothing; it binds no path | `sections` |
| `fields` | one object with named keys | `element`, whose `fields` describe that object |
| `list` | an array of objects | `element`, whose `fields` describe one row |
| `strings` | an array of bare strings | `element`, with no `fields`, and optional |

`kind` is the only key every node shares. Each kind is then closed on its own
set, so `badges` on a `list` or `path` on a `group` fails validation and names
the offending key.

Four keys mean the same thing on every kind that accepts them:

| Key | Purpose |
|---|---|
| `title` | Heading above the node. Required on a `group`, optional everywhere else. |
| `description` | One muted line under the title, saying what belongs here. Omit it if the title already says it. |
| `info` | `{overview, tips[]}`, the content of the section's info dialog, for anything longer. |
| `$comment` | A note for the next author. Ignored by the loader, every renderer, and the MCP contract. |

`path` is an array of storage keys resolved against the section root. It is
required on `fields`, `list` and `strings`, and rejected on `group`. On `list`
and `strings` it must be non-empty: an empty path addresses the containing
object, and a write there returns the new value, so the first save would replace
the section's whole stored object with one row. On a `fields` node `path: []` is
legal and useful, because it addresses the section root.

### `group`

Six keys: `kind`, `title`, `sections`, and the optional `description`, `info` and
`$comment`. A band over its children and nothing else, so it takes no `path`, no
`element` and no `fields`. `title` is required, because the band is a label.

Its `sections` are full nodes, and their `path` resolves against the section
root. A group is a visual container, not a data scope.

```json title="section_packs/profile/manifest.json"
{
  "kind": "group",
  "title": "Contact & Links",
  "description": "How to reach you and your online presence",
  "sections": [
    { "kind": "list", "path": ["contact", "emails"], "title": "Emails",
      "element": { "entity": "email", "identifier": "address", "fields": [
        { "name": "address", "required": true, "role": "title", "placeholder": "you@example.com" },
        { "name": "purpose", "required": true, "show": ["form", "badge"], "placeholder": "e.g. primary, work, personal" }
      ] } }
  ]
}
```

The shipped node also carries an `info` block and a second child list, dropped
here for length.

### `fields`

Seven keys: `kind`, `path`, `element`, and the optional `title`, `description`,
`info` and `$comment`. The value at `path` is one object, edited in place.

```json title="section_packs/preferences/manifest.json"
{
  "kind": "fields",
  "path": ["communication", "default"],
  "title": "Default Communication Style",
  "description": "Always active. How you prefer AI responses to be written.",
  "element": {
    "entity": "communication_default",
    "description": "Update-only singleton for default communication style",
    "fields": [
      { "name": "tone", "placeholder": "e.g. friendly but professional" },
      { "name": "locale", "placeholder": "e.g. British English" },
      { "name": "detail_level", "type": "longtext",
        "placeholder": "e.g. comprehensive with examples, step-by-step breakdowns when explaining code..." }
    ]
  }
}
```

### `list`

Ten keys, the most any kind gets: `kind`, `path`, `element`, and the optional
`title`, `description`, `info`, `search`, `facets`, `sort` and `$comment`.

| Key | Type | Purpose |
|---|---|---|
| `search` | boolean | Default false. A filter box over the rows. |
| `facets` | array | Field names offered as filter chips. Each must name a declared field whose `type` is `enum`, since the chips are built from the vocabulary. |
| `sort` | object | `{field, dir}`. Display order only. |

`sort.field` must name a declared field. `dir` is `asc` or `desc`. Two numbers
compare numerically and everything else compares as text; rows where the key is
missing or empty sort last, whichever direction you chose. The stored array is
never reordered.

```json title="section_packs/learning_log/manifest.json"
{
  "kind": "list",
  "path": ["entries"],
  "search": true,
  "sort": { "field": "timestamp", "dir": "desc" }
}
```

That excerpt drops the node's `element`, which every `list` requires.

### `strings`

Nine keys: `kind`, `path`, and the optional `title`, `description`, `info`,
`control`, `placeholder`, `element` and `$comment`. The value at `path` is an
array of bare strings, so there are no named keys and no field descriptors.

| Key | Type | Purpose |
|---|---|---|
| `control` | enum | `"chips"` (the default) or `"input"`. |
| `placeholder` | string | Placeholder for this node's one input. |
| `element` | object | Optional. Who may write the array over MCP. |

`"chips"` renders each string as a chip, which suits short word-like values you
add and remove but never revise. `"input"` gives each string its own editable
row with its own delete, which suits sentence-like values where a typo would
otherwise mean retyping the line.

```json title="section_packs/lifestyle/manifest.json"
{
  "kind": "strings",
  "path": ["wellness", "energy_peaks"],
  "title": "Energy Peaks",
  "description": "Times of day when you feel most focused and productive",
  "placeholder": "e.g. Early morning (6-9am), Late night (10pm-1am)...",
  "element": { "entity": "energy_peak", "identifier": "peak" }
}
```

## `element`

`element` describes one member of what its node binds: one row of a list, or the
one object a `fields` node is, or one string of a `strings` array. It is where
the MCP entity is named, and the same key means the same thing on a node and on
an array-typed field.

### On a `list`

`entity`, `identifier` and `fields` are required.

| Key | Type | Purpose |
|---|---|---|
| `entity` | string | The name an MCP client passes. Unique across the pack, `variants` included. |
| `identifier` | string | The field that names a row. Must name a declared field of this element. |
| `fields` | array | One or more [field descriptors](#the-field-descriptor). |
| `actions` | array | Any of `add`, `update`, `remove`. Default all three. |
| `description` | string | MCP-facing: what this record is, for a client choosing an entity. Distinct from a node's `description`, which is on-screen helper text. |
| `variants` | array | Extra entity names over this same stored array. |
| `parent` | string | Nested arrays only. The MCP parameter naming the enclosing row. |
| `list` | string | The stored array's own name as the contract reports it today. |

`parent` must name the enclosing element: its `identifier` bare, or that
identifier prefixed by the enclosing entity's name. `education_highlight`'s
parent is `institution`, which is `education`'s identifier; `project_tag`'s is
`project_name`, where `project`'s identifier is `name`. The loader checks the
pair against the row the element actually sits under, because the same manifest
is otherwise internally consistent with a wrong one in it.

`list` is redundant with the node's `path` and not derivable from it. Four
shipped elements carry it, reaching five of the 42 entities because
`likes_dislikes` serves `like` and `dislike` from one element. Which five follows
no rule: `interest` at path `interests` has it, `goal` at path `goals` does not.
A new pack does not need it.
If a pack already declares it, keep it, because the key is part of what
`get_schema` reports and removing it changes the MCP contract.

### On a `fields` node

The same shape, with two differences. `identifier` is optional, because a
singleton is not one of many and usually has nothing to name it by. `actions`
defaults to `["update"]`. Neither `variants` nor `parent` nor `list` is accepted.

Two of the three shipped singletons derive `identifier: null`. The exception is
lifestyle's sleep pair, whose identifier is `day_type`, a `write_only` router
selecting which fixed sub-object a client means.

### On a `strings` node or field

`entity` and `identifier` are required, there is no `fields`, and the whole
`element` is optional. Without it the array is editable in the app and invisible
to a client, which is the common case: preferences ships six `strings` nodes and
only `response_format` is in the contract.

`entity`, `description` and `parent` mean what they do above, `actions` defaults
to `["add", "remove"]`, and one key belongs to this shape alone: `bulk`, a
boolean saying whether a client may send the whole array at once under the array's
own name.

`identifier` here is the parameter name for one string rather than a field name,
and it is an ad-hoc singular that does not follow from the array's name, which is
why it has to be declared: `energy_peaks` takes `peak`, `stress_triggers` takes
`trigger`, `response_format` takes `item`. A bare string has no identity apart
from its value, so `update` is not available: you remove one and add another.

```json title="section_packs/profile/manifest.json"
{
  "name": "skills", "type": "strings", "show": ["count"], "label": "Skills",
  "placeholder": "e.g. Project management, Python, Public speaking",
  "element": {
    "entity": "work_skill", "identifier": "skill", "parent": "company", "bulk": true,
    "description": "A skill or technology used in a role. Bare strings on the parent row, like work_highlight."
  }
}
```

### `variants`

Two keys, `entity` (required) and `description`. A variant is a second MCP name
over the same stored array, same fields, same identifier, same actions,
differing in its client-facing description and nothing else.

```json title="section_packs/preferences/manifest.json"
"variants": [
  { "entity": "dislike",
    "description": "Something you dislike; stored in the shared likes_dislikes list with stance=dislike unless you send stance explicitly" }
]
```

`preferences` is what it exists for: `like` and `dislike` are two entities over
one `likes_dislikes` list, discriminated by a `stance` field. `dislike` binds no
node, so without `variants` it could not be derived at all.

## The field descriptor

`name` is the only required key, and it is the stored key.

| Key | Type | Purpose |
|---|---|---|
| `name` | string | The stored key. MCP input spellings go in `alias`. |
| `label` | string | Control label or block heading. Defaults to a title-cased `name` (`detail_level` becomes "Detail level"), so declare it only where that reads wrong. |
| `type` | enum | One of the eight below. Default `text`. |
| `values` | array | The vocabulary. Required if and only if `type` is `enum`. |
| `default` | string, boolean or number | Prefilled in the form, and applied by the MCP write path on `add`. |
| `placeholder` | string | A concrete example earns its place here; a restatement of the label does not. |
| `suggestions` | array | Chips in the Add dialog. Only the title field's are read, since a suggestion is a proposed row rather than a proposed value for some other key. |
| `required` | boolean | Default false. Derives the entity's `required`. |
| `role` | enum | `"title"`, the field that names a row. At most one per element, and a `list` row must have one. |
| `show` | array | Where the field draws. Default `["form"]`. |
| `format` | enum | `"date"` or `"datetime"`. Display only. |
| `alias` | array | Accepted MCP input spellings. `alias[0]` is the primary one. |
| `off_contract` | array | Which of `values` / `default` the MCP contract does not carry. |
| `ui_only` | boolean | Rendered and stored, in no MCP vocabulary. |
| `write_only` | boolean | In the MCP contract, rendered nowhere. |
| `exclusive` | boolean | At most one row in the list may hold this. Derives `exclusive_fields`. |
| `allow_custom` | boolean | `enum` only. Adds the free-text box, and `custom_<name>` to the contract's `optional`. |
| `pin` | object | `bool` only. `{title, empty, noun}`. Lifts the one row holding this field above the list. |
| `control` | enum | Overrides the control `type` would pick. Meaningful on a `strings` field. |
| `element` | object | One member of this field's array. Required if `type` is `list`, optional if `type` is `strings`, rejected on every other type. |
| `$comment` | string | A note for the next author. |

### The eight types

| `type` | Stores | Renders as |
|---|---|---|
| `text` (default) | string | one-line input |
| `longtext` | string | textarea |
| `enum` | one of `values` | segmented control, or a select once there are too many options |
| `date` | string | date input |
| `time` | string | time input |
| `bool` | boolean | switch |
| `strings` | array of strings | chips, or one editable row per string with `control: "input"` |
| `list` | array of objects | a nested list editor |

A field that wants a textarea says `type: "longtext"`. Nothing infers it from
the field's name any more, so a `notes` field that omits it gets a one-line
input.

`strings` and `list` are the two array types, and a `label` on either turns it
into a titled block under the row with its own add and remove. A block may not
also claim the `form` position, since the block is the field's control, and the
loader rejects that pair rather than letting the renderer discard the position.
A block's `placeholder`, `control` and `default` describe the block's own input.

### `show`

| Value | Position |
|---|---|
| `form` (the default) | a control in the edit form and the Add dialog |
| `badge` | a chip on the collapsed row, drawn from the stored value |
| `row` | the faded secondary line on the collapsed row |
| `count` | an "N topics" chip on the collapsed row. Needs an array-valued field. |
| `pin` | drawn as the star that claims the pinned slot, and nowhere else |

It is an array because one field can hold several positions at once: `status` is
a badge on the collapsed row and a control in the expanded one. Order within a
position comes from the order of the `fields` array, so one list of descriptors
fixes the form order and the badge order together.

`show: []` means stored and drawn nowhere. It is legal on a labelled array, which
draws its own block and needs no position on the row, and on a field the app
writes without ever showing, which must also say `ui_only`. Anything else with an
empty `show` is a field nothing can read and nothing can write, and the loader
says so.

### `default` and `@now`

The exact string `"@now"` is replaced by an ISO 8601 timestamp when the editor
adds a row. The MCP write path applies a `default` literally, so `"@now"` only
makes sense on a field no client can set. Both shipped uses are `ui_only`.

```json title="section_packs/learning_log/manifest.json"
{ "name": "timestamp", "show": ["row"], "default": "@now", "format": "datetime", "ui_only": true }
```

`format` is display only. The stored value is untouched, and one a date parser
cannot read is shown verbatim.

### `alias`, `write_only`, `ui_only`

Three keys for three audiences.

`alias` lists input spellings MCP accepts for a field that is rendered. `course`
is an alias of profile Coursework's `name`: the client says `course`, the app
stores `name`, and no second control appears. `alias[0]` is what the derived
contract reports, and later entries are the additional spellings `execute_modify`
accepts.

```json title="section_packs/profile/manifest.json"
{ "name": "name", "required": true, "role": "title", "alias": ["course"],
  "placeholder": "e.g. Macroeconomics, Data Structures" }
```

`write_only: true` is in the contract and rendered nowhere:
`conversation_metadata` and `related_entries` on learning_log entries, profile's
`new_label`, and lifestyle's `day_type`. `ui_only: true` is the mirror, rendered
and stored and in no MCP vocabulary. Every `ui_only` field in the shipped packs
is a timestamp the server writes and a client must not set.

No two fields in one element may share a `name`, and no `alias` may collide with
another field's `name` or with another field's `alias` in the same element.

### `off_contract`

`["values"]`, `["default"]`, or both. The MCP write path rejects a value outside
`valid_values` and applies `field_defaults`, so deriving those from a form that
offers a closed vocabulary or prefills a default would start enforcing and
writing things the contract does not carry today.

```json title="section_packs/profile/manifest.json"
{ "name": "status", "type": "enum", "values": ["current", "completed", "incomplete"],
  "show": ["form", "badge"], "default": "current", "off_contract": ["values", "default"] }
```

Five fields in the shipped packs declare it. A new pack normally declares
nothing, and its form and its contract agree.

### `pin`

All three keys are required: `title`, `empty`, and `noun`, which is what the slot
is called in a control's accessible name ("primary" gives "Make Brutalist
primary"). `pin` sits on the field it pins, and only a `bool` field may carry it.

```json title="section_packs/aesthetics/manifest.json"
{
  "name": "primary", "type": "bool", "show": ["pin"], "exclusive": true,
  "pin": {
    "title": "Primary aesthetic",
    "empty": "No primary set yet. Star a style below to make it your design language.",
    "noun": "primary"
  }
}
```

The lifted row is excluded from the list below rather than shown twice, the field
never renders as an editable control or appears in the Add dialog, and every
other row gets a star to claim the slot.

<Callout type="warn">
Pair `pin` with `exclusive: true`, as aesthetics does. `pin` governs the editor;
`exclusive` derives the `exclusive_fields` both writers honour. Without the pair,
an MCP client can set a second one.
</Callout>

### `allow_custom`

`enum` only, and it replaces the `custom_` field-name prefix that nothing used to
declare anywhere.

```json title="section_packs/goals/manifest.json"
{ "name": "type", "type": "enum", "allow_custom": true, "show": ["badge"],
  "values": ["career", "learning", "personal", "health", "financial", "creative", "other"] }
```

That puts a free-text box under the vocabulary in the form, and `custom_type` in
the derived entity's `optional`.

## The derived contract

No manifest declares an entity. `pack_loader.derive_entities` computes the
contract from the field descriptors and `get_schema` ships the result, so a
field's stored name, type, vocabulary, default and requiredness are declared
once.

| Contract key | Comes from |
|---|---|
| entity name | `element.entity`, plus one per `variants` entry |
| `identifier` | `element.identifier`, reported as that field's `alias[0]` if it has one; `null` on a `fields` element that declares none |
| `required` | fields with `required: true`, spelled `alias[0]` if present, preceded by the enclosing row's parameter for a nested array |
| `optional` | every other field, same spelling rule, plus `custom_<name>` for each `allow_custom` enum |
| `actions` | `element.actions`, or the default for the element's kind |
| `valid_values` | each `enum` field's `values`, unless `off_contract` excludes them |
| `field_defaults` | each field's `default`, unless `off_contract` excludes it |
| `exclusive_fields` | fields with `exclusive: true` |
| `parent` | `element.parent` on a nested array |
| `list` | `element.list`, copied verbatim |
| `description` | `element.description`, or the variant's |

`ui_only` fields are dropped from the contract entirely, `write_only` fields are
in it, and `$comment` never reaches a client. Read what your pack derives before
opening a PR:

```bash
cd backend && python3 -c "
import json, pack_loader
print(json.dumps(pack_loader.derive_entities(json.loads(
    open('section_packs/<key>/manifest.json').read())), indent=2))
"
```

### `mcp_entities`

One top-level key holds hand-written entities, in the v1 entity shape, for a
storage path no node can imply. Two of the 42 shipped entities need it:
`knowledge.knowledge` writes into `knowledge[category]` with the client choosing
the category, and `preferences.preference` is a generic key-value store.

| Key | Type | Required |
|---|---|:--:|
| `identifier` | string | ● |
| `required` | array | ● |
| `optional` | array | ● |
| `actions` | array | ● |
| `description` | string | |
| `valid_values` | object | |
| `field_defaults` | object | |
| `exclusive_fields` | array | |
| `parent` | string | |
| `list` | string | |
| `$comment` | string | |

```json title="section_packs/preferences/manifest.json"
"mcp_entities": {
  "preference": {
    "actions": ["add", "update", "remove"],
    "required": ["key"],
    "optional": ["category", "value"],
    "description": "Generic key-value preference with category support",
    "identifier": "key"
  }
}
```

<Callout type="warn">
This is not an escape hatch. A hand-authored entity beside a derived one is the
drift the format exists to stop, so a third entry needs an argument rather than a
commit.
</Callout>

| Question | Ask |
|---|---|
| What keys does a manifest accept? | `backend/section_packs/meta_schema.json` |
| How do I author one? | `docs/CONTRIBUTING-PACKS.md` in the repository |
| What entities exist right now? | `get_schema()` against a running server |

Every table on this page summarises the first of those. Where they disagree, the
schema is right and this page is stale, so please fix it.
