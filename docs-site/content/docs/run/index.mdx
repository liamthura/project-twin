MyGist ships as **one container** serving four things on a single origin: the
web UI at `/`, the REST API under `/api`, the MCP endpoint at `/mcp`, and this
documentation at `/docs`. There is no separate frontend service and no Node
runtime in production — the SPA and these docs are both static output built
into the image.

## What you are running

| Piece | Where | Notes |
|---|---|---|
| Web UI | `/` | Vite + React, built into the image |
| REST API | `/api` | Bearer-token auth; `/api/health` is public |
| MCP endpoint | `/mcp` | Mounted at root so it resolves without a redirect |
| Docs | `/docs` | This site, statically exported |
| Interactive API docs | `/api/docs` | Swagger; ReDoc at `/api/redoc` |

## What you need

Postgres, and nothing else. [pgvector](/run/database) is optional — without
it search degrades to full-text only rather than breaking. An embedding provider
is optional on top of that.

State that lives outside the repo — DNS, the reverse proxy, the deployment
platform — is written down in [Infrastructure](/run/infrastructure), because
it is otherwise only in a dashboard.
