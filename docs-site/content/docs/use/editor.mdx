The web UI at the root of your instance is a full editor for everything MyGist
stores. Open the instance in a browser and sign in with your username and
password.

It is often the faster tool. Correcting six fields is a few clicks, against
several turns of conversation.

## Getting around

Sections appear in the rail down the left. Within a section:

- **Lists** show one row per entry. Click a row to expand it and see its fields.
- **Scalar fields** such as your name, role and bio are plain forms.
- **Tag-style fields** are chips: type to add, click the × to remove.
- **Nested lists** live inside an expanded row. A job's highlights and skills, a
  course's topics, a project's references.

## Saving

Auto-save is on by default. Changes are written a moment after you stop typing,
and the status next to the toggle tells you where things stand: *Saving…*,
*Saved just now*, or *Unsaved changes*.

Turn auto-save off and a **Save now** button appears instead, so you can make a
batch of edits and commit them in one go. The status then reads *Unsaved
changes* until you press it.

<Screenshot
  src="/screenshots/editor-entry-expanded.png"
  caption="An expanded list entry"
/>

The editor is **generated from the same section packs** the server writes
through. A pack that declares a field gets a control for it. That is why the UI
and the AI tool vocabulary stay in step: there is no second definition to fall
out of date.

## On a phone

The editor works on a small screen. A few things move:

- Entry titles get the full width of the row, and status chips drop to a second
  line underneath.
- Section navigation collapses from the rail into a dropdown.

## Sections

Open the **Sections** manager to turn sections on and off.

- **Media** and **aesthetics** start off. Turn them on if you want them.
- **Profile**, **preferences** and the **learning log** are always on and cannot
  be disabled.
- Everything else is on by default and can be switched off.

Disabling a section keeps its data exactly as it is. The section stops being
offered to AI clients and stops appearing in the editor, and comes back
unchanged when you re-enable it.

## Account

The settings dialog has five tabs: **Account**, **Server**, **Tokens**,
**Connected apps** and **Data**. Three of them matter for day-to-day use.

### Account and server

Your password, under Account: set one if you registered without, or change the
one you have. Minimum eight characters. **Server** is which instance the UI is
pointed at, for a browser that is not being served by the instance itself.

### Tokens

Issue named tokens for AI clients, see when each was last used, and revoke any
of them.

<Callout type="warn">
A new token's value is shown **once**, when you create it. Copy it immediately.
It cannot be read back, only replaced.
</Callout>

Use one token per client, so revoking a token from a machine you no longer have
does not disconnect everything else.

### Data

**Export** downloads your whole persona as a zip of JSON files, one per section:
the same structured data the tools read.

**Import** takes one back. Two modes:

| Mode | Does |
|---|---|
| **Replace** | Overwrites your existing data with the backup's contents |
| **Merge** | Combines the backup with what is already there |

Export then import is also how you move between servers. It needs no database
access at either end.

## Editor-only actions

- **Bulk corrections** that would be tedious one tool call at a time.
- **Seeing everything at once**, including fields no read scope surfaces.
- **Fixing a bad write**: if a client stored something under the wrong entry,
  correcting it here is immediate.
- **Exporting and importing** your data.

## Tool-only actions

- **Linking entries.** The editor shows relationships but does not author them.
  See [Relations](/use/relations).
- **Capture suggestions**, which are a conversation feature by nature.

## Editing in both at once

<Callout>
Both write to the same rows. There is no sync step and no conflict resolution:
whichever wrote last wins.

So avoid editing the same entry in the browser and in a conversation at the same
moment. Between the two, at different times, is completely fine.
</Callout>
