title: Quick start
description: From nothing to a connected assistant in about ten minutes.
---

By the end of this page you will have an account, a connected AI client, and a
few real facts stored.

<Callout>
This page assumes a MyGist server is already running, either a hosted instance
or one you started. If you need to stand one up first, follow
[Self-hosting](/run/self-hosting) and come back here.
</Callout>

Throughout, `https://mygist.thuradev.qzz.io` stands in for a hosted instance and
`http://127.0.0.1:1120` for one running on your own machine. Swap in your own
address.

<Steps>

<Step>

## Create an account

Open the instance in a browser. On the welcome screen, choose **Create an
account**, pick a username, and set a password of at least 8 characters.

<Screenshot
  src="/screenshots/welcome-signup.png"
  caption="The welcome screen, with 'Create an account' selected"
/>

<Accordions>
<Accordion title="Prefer to do it from a terminal?">

```bash
curl -X POST https://mygist.thuradev.qzz.io/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username": "you", "password": "your-password"}'
```

The response carries your first token:

```json
{ "user_id": "…", "username": "you", "token": "…" }
```

</Accordion>
</Accordions>

There are three kinds of credential, and it helps to know which is which:

| | Used by | Expires |
|---|---|---|
| **Username and password** | You, in a browser | Sign-in sessions last 30 days |
| **An OAuth connection** | A client that can open a browser | Short-lived, and the client renews it itself |
| **A bearer token** | Clients and scripts that cannot | Never, until you revoke it |

All three point at the same persona. Every read and write is scoped to the
account behind the credential, so two accounts on one server cannot see each
other.

</Step>

<Step>

## Connect your AI client

MyGist's MCP server runs over HTTP, so clients connect by **URL** rather than by
launching a local process:

```text
https://mygist.thuradev.qzz.io/mcp    # a hosted instance
http://127.0.0.1:1120/mcp             # one on your own machine
```

Give the client that address. Where it supports OAuth, that is the whole
configuration: no token to create, paste or renew.

A browser opens, you sign in, and a consent screen names the client and the
account before anything is granted:

> **Claude Desktop** wants to connect to **your-username**'s persona

Check that name, then choose what to allow. Reading is always on; suggesting
changes and writing directly are both checked to begin with, and you can uncheck
either. [Other clients](/use/clients#choose-what-to-grant) explains what each
line means, and how to change your mind later.

Approve it and you are done. The client holds a short-lived token that it
refreshes on its own.

<Callout>
OAuth has to be switched on for the instance you are connecting to. The hosted
instance has it; a server you started yourself does not unless you set
`AUTH_MCP_RESOURCE`. To check:

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  https://your-instance/.well-known/oauth-protected-resource
```

`200` means OAuth is available. `404` means use a token instead, below.
</Callout>

<Accordions>
<Accordion title="No OAuth? Connect with a token instead">

Needed for a client that has no browser to open, one that has not implemented
remote MCP authorization yet, or an instance with OAuth switched off. It is the
same access, configured by hand.

Start by creating the token. Open **Account → Tokens** and make one, named
for what it is for, like `claude-desktop` or `laptop-cli`.

<Screenshot
  src="/screenshots/settings-tokens-new.png"
  caption="Account → Tokens, with a new token just created"
/>

<Callout type="warn">
The token is shown **once**, at the moment it is created. Copy it now. There is
no way to read it back later, only to revoke it and issue a new one.
</Callout>

Use a separate token for each client, so revoking one does not disconnect
everything else you have set up.

For Claude Desktop, edit the config file:

- **macOS**: `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "mygist": {
      "url": "https://mygist.thuradev.qzz.io/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN"
      }
    }
  }
}
```

For a local server, use `http://127.0.0.1:1120/mcp`.

Then restart Claude Desktop completely: quit it, do not close the window.

For Claude Code, one command does it with no file editing:

```bash
claude mcp add --transport http mygist https://mygist.thuradev.qzz.io/mcp \
  --header "Authorization: Bearer YOUR_TOKEN"
```

<Callout>
Config shapes for remote MCP servers have changed between client versions, and
clients disagree about where headers go. If the shape above does not match what
your client expects, check that client's own documentation. The URL and the
bearer token are the parts that never change.
</Callout>

</Accordion>
</Accordions>

For anything not named here, see [Other clients](/use/clients).

</Step>

<Step>

## Check it works

Ask the assistant something it can only answer by looking:

> What do you know about me?

A connected client calls `get_context` and answers from your persona. Your
account is empty, so the honest answer is "almost nothing". That is the correct
first result, and it proves the connection works.

<Screenshot
  src="/screenshots/chat-fresh-account.png"
  caption="A fresh account answering honestly"
/>

If the tools do not appear at all, jump to
[Checking the connection](/use/clients#checking-the-connection).

</Step>

<Step>

## Put something in it

An empty persona is not much use. Spend five minutes seeding it. Say what is
true:

> I'm a backend developer at Acme, based in Manchester.
> I'm building a project called Solterra — a solar output tracker in Python.
> I prefer short answers with code first and explanation after.
> Add Postgres to my skills as something I'm confident with.
> I'm learning Rust at the moment.

The assistant picks the right entity for each and calls `persona_modify`. You
should see the tool calls happen, and a confirmation of what was stored.

<Screenshot
  src="/screenshots/chat-several-writes.png"
  caption="Several facts being written in one conversation"
/>

If you would rather click than type, everything is editable in the
[web editor](/use/editor) too.

</Step>

<Step>

## Try it in a real conversation

Start a fresh chat and ask something that needs the context:

> Help me plan next week's work.

A client that reads your persona first already knows your role, your current
project, and that you want short answers, without you having said any of it.

</Step>
