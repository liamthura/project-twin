This half of the documentation is for people who *use* MyGist. It assumes a
server is already running, either one you host or one someone hosts for you. If
you need to start one first, go to [Self-hosting](/run/self-hosting).

## The short version

Once an AI client is connected, it can do three things:

1. **Read** who you are, at the level of detail it needs.
2. **Search** everything you have stored, and pull up single entries.
3. **Write** new facts when you ask it to.

You never call any of this yourself. You talk normally, and the client decides
which tool to use.

## How a conversation uses it

At the start of a conversation, a well-behaved client calls `get_context` and
gets back a compact summary: your name, your role, how you like answers written,
what you are working on. A slice of the persona, sized for the conversation.

When something specific comes up later, it searches:

```text
search_context("postgres")   →  about ten ranked snippets, each with an id
get_entity(["proj_a1b2"])    →  the full entry, for the one that matters
```

Two small calls do the work of one large one, and that pattern is what the whole
tool set is built around. [Reading](/use/reading) covers it properly.

## When the tools run

MyGist's tools are **passive**. They run when a client calls them, and never
otherwise. Nothing watches your conversation in the background, and nothing is
written without an explicit call.

So if you mention halfway through a chat that you have started learning Rust,
that fact is *not* saved. You have to ask, or you have to turn on suggestions at
the start of the conversation. [Capture](/use/capture) explains both, and why it
works this way on purpose.
